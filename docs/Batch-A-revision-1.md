# 批次 A 修订 1：注音与音频审阅稿、逐轮交流和地图辨识度

确认日期：2026-10-17。状态：用户已确认方案并授权先提交本文，随后实施。本文件记录本次实施基线，不表示以下功能已经完成；实际结果见开发进度与修订验收记录。

## 1. 范围与优先级

本修订在批次 B 前完成，基于批次 A 已有工程继续修改。用户最新要求优先于旧稿中三种输入并列、点击才见表达卡、注音/音频先通过审核才制作或展示的安排。四站交流目标、规则决定进度、保存成功后才完成、密钥仅在服务端等约定保留。

本轮不开展其他三站业务集成、生产部署或用户研究。允许制作真实的上海话注音和 TTS 待审稿供用户审阅；制作完成不等于语言审核通过，不伪造审核人或批准记录。正式发布审核与审阅预览分开。

## 2. 注音与沪语台词

- 当前南翔所有可出现的店员台词、核心示范回答、数量/商品/堂吃选项与关键短语均补上沪语汉字候选及拉丁注音，不再用空白的 Awaiting review 代替内容。
- 先补齐原本只有普通话/英文释义的店员沪语台词，再按统一拼写、标调与分词规范制作注音；记录依据与存疑读法，不把普通话拼音冒充沪语。
- 汉字与注音按词组对齐，保留当前界面语言的释义。注音默认开启、可隐藏，并保存偏好；隐藏注音不隐藏汉字、释义和音频。
- 明确显示“审阅稿”，用户可先看、听并提出修改。所有内容批准状态保持真实。中文近似读音仍只在中文模式按需显示，本轮不把它当注音或音频的替代物。
- 提供逐条审阅清单，至少含 ID、沪语原句、注音、中文/英文意思、对应声音和需要核对之处。

## 4. 南翔逐轮交流

### 4.1 每次一个问题

默认为商品 → 数量 → 堂吃/外带 → 核对。每轮只呈现当前问题及对应选项；已保存订单压缩为可展开摘要。回答后有即时反馈，再进入下一问题。

逐轮约束界面提问，不限制用户语音能表达的信息量。一句话明确说出两份小笼包外带时，接收所有明确字段并跳过已回答问题；未知字段不凭目标补齐。单位、否定、修改、冲突继续触发对应澄清，旧确认在修改后失效。

### 4.2 角色动态

保留当前柜台艺术方向，以角色、当前台词和回答为中心。增加待机、问话、倾听、处理、接收、澄清、核对、装袋/递出等可区分的状态。说话状态与实际音频播放关联，提供简单口型与手势，不宣称逐音素口型同步。

录音时停止应用播放；保存成功后才出现打包成功动作，场景显示两份的明确结果。减少动态时使用静态姿态，不影响问题、语音、输入和完成。刷新恢复当前对话，不自动重播录音、递袋或重复提交。

### 4.3 移除 Type

主流程只保留“说话”和“选择回应”，从开始即可使用。移除独立自由文字输入入口、Type 标签、依赖文本框的“填入回应”和相关文案。已有历史 text/voice_edited 记录仍可读，不删除历史数据。

语音路径为主动录音 → 本地回听 → 明确识别 → 只读转写/语义核对 → 使用这句话、重新录音或改用选项；不再跳到文字编辑框。原转写及来源保留，识别错误不能被当作发音错误。

### 4.4 当前轮直接展示语言支持

问题和相关回答均直接展示：词组拉丁注音（上方）＋沪语汉字＋当前语言释义（下方）。不要求打开 Pocket phrase book 才见当前轮提示。表达合集继续可用于复习，中文/英文各展示自己的解释，不把两套释义同时堆在每一轮。

## 5. TTS 制作、保存与审阅

- 采用已有 qwen3-tts-flash + Jada 适配器，生成店员整句、核心回答和关键选项的真实上海话待审样音。允许单独的 review-draft 制作入口，不伪造已审语言状态以通过旧生产门槛。
- 固定句预先生成、保存、复用，不在用户每次播放或每次对话时重新合成。只有原文、音色或制作设置变化时生成新版本。
- 开发时保存在项目素材目录，应用通过稳定路径播放；部署后随静态资源或持久对象存储发布。临时供应商 URL 不能成为长期素材地址，不能依赖 Vercel 函数临时文件持久保存。
- 记录文字/注音版本、实际 TTS 输入、模型/音色、生成日期、时长、校验值与待审状态。输入只包含沪语台词，不混入释义或拉丁注音。
- 首轮交付常速待审音频与逐句试听；用户选定常速读法后再制作并听审慢速。现有 Flash 不假定支持语速指令；慢速可评估保音高减速，不能复制常速假充慢速。
- 有限核对/澄清分支使用整句素材，避免逐字拼接。真实开放式对话的实时 TTS 留待有需求时评估。
- 教学音频可提交为明确待审的项目资产；私人用户录音、密钥、原始诊断日志不提交。真实 API 调用记录实际用量，复用已有同版本文件以避免重复生成。

依据：[官方 Jada 音色](https://help.aliyun.com/en/model-studio/qwen-tts-voice-list)、[TTS API 与 24 小时临时链接](https://help.aliyun.com/zh/model-studio/qwen-tts-api)。支持音色不代表具体读法已经合格。

## 6. 实施顺序与文件交接

1. 本文及关联决定先提交 Git 并推送，作为已确认基线。
2. 冻结首轮沪语脚本/注音审阅稿，建立逐句清单；同步准备四站独立建筑和角色动作。
3. 实现审阅样音生成及保存，生成常速声音；将可播放稿接入问题和回答。
4. 改造逐轮界面、移除 Type、接入角色状态和内嵌语言支持，复用后端保存与规则。
5. 检查中英桌面/手机、注音开关、问题推进、语音核对、动画/音频和回归，保存截图与真实验收记录，更新进度并提交推送。
