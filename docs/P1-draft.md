## 3. 目标用户与双语策略

### 3.1 已确认的目标用户

产品同时覆盖两类学习者：

| 用户群体 | 已知特点 | 产品需要支持的需求 |
| --- | --- | --- |
| 会普通话、不会上海话的用户 | 可以使用普通话理解说明，上海话为入门水平 | 通过中文界面理解任务并学习上海话 |
| 主要使用英语、可能不认识汉字的用户 | 使用英语理解说明，不能假定其具备汉字阅读能力 | 通过英文界面理解任务，同时接触核心上海话表达的汉字 |

### 3.2 已确认的语言与展示要求

- App 提供中文和英文版本，用户可以在设置中切换。
- 核心上海话表达的汉字在两种语言模式下均保留。
- 英文模式仍展示核心表达的汉字；其他说明性内容使用英语，包括 Instructions 和读音辅助说明。
- 不应要求英文用户通过阅读汉字来理解操作与任务。

| 内容类型 | 中文模式 | 英文模式 |
| --- | --- | --- |
| 导航、设置、按钮、系统提示 | 中文 | 英文 |
| 任务说明、操作引导、文化介绍 | 中文 | 英文 |
| 核心上海话表达 | 展示上海话汉字 | 保留并展示上海话汉字 |
| 核心表达的意思 | 提供普通话释义 | 提供英文释义 |
| 读音辅助 | 面向中文用户提供辅助 | 面向英语用户提供辅助，相关说明使用英文 |

### 3.3 读音与音频：已确认方案与待制作内容

2026-10-17，用户在提供多邻国上海话学习截图并讨论注音方式后，明确同意采用以下方案：

- 两种模式保留核心上海话汉字和对应语言释义，共用一套上海话拉丁字母注音；默认显示、可隐藏，并按词组与汉字对齐。
- 中文模式配中文读法说明，英文模式配英文读法说明；不能假定英语用户会普通话拼音或能直接读懂这套注音。
- 仅中文模式提供“中文近似读音”入口，默认收起，点击后显示经过审核的谐音辅助，并标注“近似读音，请结合音频”。英文模式不显示该入口或内容。
- 上海话原句、释义和近似读音分开维护与呈现；谐音不替换原句或释义。
- 两种模式共用上海话常速、慢速示范；播放入口紧贴句子，注音清楚可读，示范音频作为主要读音依据。
- 先以南翔的点数量、表达外带和确认订单三类核心表达制作样例，再扩展其他表达。

仍需完成的制作与验证：

- 具体字母、分词和符号规范，以及逐句注音和中文谐音文本，均需由流利上海话使用者核对；不能直接把截图拼写当作已定稿标准。
- 原句、释义、实际读法、音频和辅助文本逐条对应；请中文初学者试读谐音，检查是否产生明显误读。难以用汉字近似的声音使用发音说明和音频帮助。
- 常速、慢速音频的制作与审校尚未完成；自然语块跟读、试读回听和首次读音引导继续保留为设计建议。
- 具体学习循环、音频类别、帮助与表达卡规格见完整方案第 4.2、4.5 节；此次确认不代表所有 UI 或学习细节已获整体认可。

### 3.4 已讨论、尚待确认的交互细节

- 表达卡、示范句和关键学习对话采用一致的语言展示规则。
- 核心汉字、释义、默认可隐藏的拉丁注音及仅中文模式展开的近似读音已按第 3.3 节确定；具体卡片尺寸、排版和交互动画继续设计。
- 切换语言时保留当前任务进度和对话状态。
- 两种语言版本使用相同的核心任务与完成标准，学习支持可以适配用户的语言背景。
- 记录界面语言及语言切换事件，以支持后续用户体验分析。
- 上海话转写、普通对话文本和其他汉字内容在英文模式中的展示边界，已在四站共同约定第 3.3 节提出具体建议，待整体审阅。

## 5. 学习目标、任务完成方式与首版范围

### 5.1 已确认的产品目标与输入原则

产品支持用户在情境中理解核心上海话表达，并借助释义、读音辅助和示范音频尝试简短交流。采用“鼓励开口，允许文字或按钮完成任务”的方式。

- 语音作为主要入口，鼓励用户尝试说上海话，并提供读音与示范音频支持。
- 文字和按钮输入始终可用，用户可以主动切换，不必先经历语音失败。
- 不要求用户至少进行一次语音尝试才能继续或完成任务。
- 用户通过语音、文字、按钮或组合方式达成任务的交流目标，均可以记为任务完成；每站的具体内容与完成条件仍需单独定义。

### 5.2 已确认的完成与记录原则

分别记录“任务是否完成”和“用户进行了哪些语言练习”：

| 记录维度 | 含义 |
| --- | --- |
| 任务完成 | 是否达成该场景预先定义的交流目标 |
| 语音尝试 | 是否尝试语音输入；一次尝试不自动代表表达正确或已掌握口语 |
| 输入方式与切换 | 使用了语音、文字、按钮中的哪些方式，以及切换情况 |
| 重试与帮助 | 语音或任务重试情况，以及示范音频、读音辅助、表达卡和人工帮助的使用情况 |

例如：用户通过按钮完成“两份小笼包外带”，应记录为“任务完成、未进行语音尝试”，不能据此判定用户已经掌握相应的口语表达。该站交流目标已确认，具体流程与完成判定仍需细化。

后续分析可关注用户在哪些情境愿意开口、何时切换输入方式，以及使用帮助后是否再次尝试语音。具体数据字段与统计口径后续细化。

如用户研究需要确保参与者体验语音，可在研究流程中安排引导练习；是否采用及如何安排尚待确定，不作为 App 的通关门槛。

## 6. 场景任务方案

### 6.1 上海老饭店

#### 已确认的交流目标

保留 proposal 中的交流目标：**表达不吃辣的偏好 → 请求推荐 → 确认菜品**。

用户需要练习表达自己的口味偏好、向店员询问推荐，并确认一道符合偏好的菜品。沿用第 5.1 节的输入原则：鼓励语音，允许使用文字、按钮或组合方式完成。

#### 已提出的任务框架：详见单站草案，待审阅

| 项目 | 工作草案 |
| --- | --- |
| 情境 | 用户进店点菜，希望得到符合口味偏好的推荐 |
| 交流流程 | 店员欢迎 → 用户表达偏好并询问 → 店员推荐 → 用户选择并确认 |
| 完成条件 | 建议同时满足用户表达不辣偏好、用户请求过推荐、选择不辣菜及确认当前选择；推荐不能由店员自行发出就视为用户已询问 |
| 学习支持 | 可随时查看表达、听示范，并使用语音、文字或按钮回应 |

以下内容已在 [老饭店独立草案](Shanghai-old-restaurant-draft.md) 形成建议规格；实际语音内容与视觉资产仍需制作审核：

- 菜单、菜品数量及其口味信息。
