## 1. 本站想带来的体验

前三站偏向购买与核对，这一站让用户在茶桌旁短暂停留，对招待作出回应。完成目标为**表达对茶的正面评价，并向店家道谢**，可以一句完成，也可以分轮表达。

建议地图名“湖心亭茶楼 / Huxinting Teahouse”，任务标题“喝一盏茶，说声谢谢 / Enjoy some tea and say thank you”。时间约 3–4 分钟，不用强制动画或额外问题拉长停留。

明确这是虚拟角色练习：任务设定用户喜欢这杯茶，无需真实饮茶，也不把台词当作用户真实口味反馈。如果不愿扮演，可以查看表达、返回或稍后再做，不强迫用户声称自己的真实喜好。

本站不设置付款、冲泡知识测验、茶叶品种考试、倒茶手势评分或自由情感聊天。点茶杯与看窗景是可选探索，不是交流通关条件。

## 2. 页面与体验流程

主路径：地图 → 入座和任务 → 店员请饮茶 → 用户评价/道谢 → 自然回应与本站回顾 → 查看当前路线进度。

| 页面 ID | 呈现 | 用户动作 | 状态说明 |
| --- | --- | --- | --- |
| TEA-01 地图卡 | 建筑小图、茶杯、本站状态、任务预告 | 进入/继续、关闭 | 四站可自由进入，茶楼可被首先访问 |
| TEA-02 入座 | 窗边茶桌、店员、任务说明，短倒茶动作 | 开始交流、跳过转场、返回 | 不要求点杯或观看完动画才能开始 |
| TEA-03 茶桌交流 | 当前对话、可选物件、回复区、简短目标提示 | 说/写/选、听重播、打开帮助 | 评价和道谢分轮累积，修正可更新 |
| TEA-04 表达抽屉 | 赞茶、道谢、重说；完整双语读音支持 | 听、试读回听、填入、关闭 | 查看不算已表达 |
| TEA-05 本站回顾 | 店员自然致意、本站完成、两类表达卡 | 去路线回顾、回地图、重练 | 无订单确认步骤，完成保存后才出现 |
| TEA-06 路线回顾 | 四站真实状态、练习事实、继续/重练入口 | 继续未完成站、重练、结束本次 | 进入茶楼或完成茶楼不等于全程完成 |

### 2.1 任务卡

中文：“想象你刚尝过这杯茶，而且很喜欢。试着告诉店家茶很好喝，并谢谢对方。”

English: “Imagine you've tried this tea and enjoyed it. Tell your host that you like the tea, and thank them.”

开始后只保留轻量“本次练习：评价茶、道谢 / This conversation: appreciate the tea and say thanks”。这两个目标的满足状态是实际回应后的记录，不在入座时自动点亮。

### 2.2 茶桌交流

店员说“请喝茶，觉得怎么样？”用户可说“茶很好喝，谢谢”，一次结束；也可先评价，听到自然回应后再道谢。

只有评价时，店员说“很高兴你喜欢”。界面在回复区轻提示“还可以谢谢招待你的人 / You can thank your host, too.”，不让角色说“你还没谢谢我”。

只有道谢时，店员自然回应“不客气。茶喝起来怎么样？”，保留已经表达的感谢，只补评价。用户先说谢谢不算顺序错误。

输入按钮建议为“评价这杯茶 / Comment on the tea”“向店家道谢 / Thank your host”“一起表达 / Say both”。点击后展开实际句子和意义，选中形成草稿，再明确提交；不点击按钮就自动记意图。

## 3. UI、空间与动作

### 3.1 建议艺术方案

| 要素 | 设计细节 |
| --- | --- |
| 画面气质 | 安静、明亮、留白较多，茶具和窗景细节精致，形成旅程收尾感 |
| 色彩 | 浅米白 #F4F1E7、浅青灰 #DCE5DF、深茶绿 #31584C、木棕 #967455，暗金 #A88443 少量点缀 |
| 构图 | 前景茶杯/茶壶，中景店员与桌面，后景窗格/水面示意；窗景为艺术创作，不声称精确实景视角 |
| 角色 | 原创招待角色，欢迎/斟茶、倾听、回应喜欢、接受道谢四种关键姿态；尊重日常自然表达 |
| 物件 | 茶杯、茶壶、茶盘、桌沿和窗景；文字和任务 UI 分层，茶具不遮挡按钮 |
| 动态 | 可跳过斟茶、轻微水面或茶汽、结束致意；减少动态时全部有静态结果 |
| 声音 | 可选轻环境声，默认关闭；无必须听到的环境声音提示，录音期间全部停止 |

桌面用横向窗景和茶桌表现空间，店员与交流面板保持清楚关系；底部实色回复区承担长句，不把文字浮在水纹上。

手机采用较近的茶杯与店员构图，窗景作为上半部背景。当前对话与录音/文字入口在下半部；帮助抽屉展开时仍留少量店内上下文。打开键盘可以折叠物件区域，不让输入挤到屏幕外。

### 3.2 物件与动效边界

- 点茶杯可打开“茶 / Tea”词语帮助或核心评价表达；不等于饮茶、不记录正面评价。
- 点窗景可打开地点文化卡；不影响任务，不把“风景好看”自动当作评价茶。
- 倒茶只是可跳过的到店动作；不能要求拖动茶壶或完成手势才让不会操作的用户继续。
- 角色倾听、回应和接受道谢各有状态，但不依赖实时口型或情绪识别。
- 两个意图都满足且保存后，角色微笑致意，展示完成卡；回应处理过程中不提前播放结束动作。
- 完成卡不覆盖整个场景太久；用户可直接回顾表达或回地图，全部操作支持键盘和读屏。

## 4. 学习内容与双语呈现

### 4.1 核心表达

| ID | 上海话汉字候选，待审校 | 普通话意思 | English meaning | 用途 |
| --- | --- | --- | --- | --- |
| E10 | 搿茶老好吃个 | 这茶很好喝。 | This tea is really good. | 表达对茶的正面评价 |
| E11 | 谢谢侬 | 谢谢你。 | Thank you. | 向招待者道谢 |
| E12 | 请侬再讲一遍 | 请再说一遍。 | Could you say that again? | 请求重复 |
| E01 | 侬好 | 你好。 | Hello. | 可选问候 |

E10 的汉字候选尤其要检查自然度和当地使用习惯，不因为写在草案中就视为正确教材。E11/E12/E01 复用共享内容库。

卡片标准仍为汉字＋词组对齐拉丁注音＋对应语言意思＋常/慢速音频；中文近似读音默认收起，英文完全不显示。中文释义使用“好喝”，不能只展示候选汉字让普通话用户猜词义。

可另提供合并句“这茶很好喝，谢谢你”的完整示范，作为 E10/E11 的组合使用，不增加一个必学表达组。组合句需单独审核、注音和整句音频，不能直接把两个音频硬接当自然上海话。

### 4.2 可接受的语义范围

| 用户表达意思 | 建议判断 | 说明 |
| --- | --- | --- |
| 这茶很好喝 / This tea is good | 正面评价 | 明确对象是茶 |
| 很香，我喜欢 / It's fragrant; I like it | 正面评价 | 在当前茶话题中明确表达喜欢 |
| 还不错 / Not bad | 可接受的正面评价 | 在茶上下文里表示温和认可，不强求夸张词 |
| 我喜欢 / I like it | 上下文清楚时可接受 | 记录对象由当前茶问题消解 |
| 谢谢 / Thanks | 致谢 | 在直接与店员交流的当前上下文可接受 |
| 杯子很好看 / The cup is beautiful | 不满足茶味评价 | 可自然回应，但需要补茶的评价 |
| 风景不错，谢谢 / Nice view, thanks | 只满足致谢 | 评价对象是景色，不能挪给茶 |
| 茶不好喝 / The tea isn't good | 不满足正面评价 | 不因包含好喝/good 判对 |
| 不要说谢谢 / Don't say thank you | 不是致谢行为 | 否定或讨论表达，不等于实际感谢 |
| 我该说“谢谢”吗？ / Should I say “thank you”? | 询问学习帮助 | 不能把引用中的词当作已经道谢 |

以语义和上下文判定，不使用只匹配“好”“谢谢”的关键词规则。普通话或英语语义回应同样可完成，但不被记作上海话口语表现。

### 4.3 关键界面文案

| 用途 | 中文 | English |
| --- | --- | --- |
| 表达提示 | 试着说说你喜欢这杯茶 | Try saying that you enjoyed the tea |
| 道谢提示 | 还可以谢谢招待你的人 | You can thank your host, too |
| 对象澄清 | 你是在说这杯茶，还是窗外的景色？ | Do you mean the tea or the view? |
| 情境提醒 | 这次角色练习是表达喜欢这杯茶。需要时可以看看怎么说。 | In this role-play, you're practicing saying you enjoyed the tea. Use the phrase help if you like. |
| 单站完成 | 你表达了对茶的喜爱，也向店家道了谢。 | You said you enjoyed the tea and thanked your host. |
| 未全程完成 | 已完成 2 / 4 站，还可以继续探索 | You've completed 2 of 4 stops. You can keep exploring. |
| 全程完成 | 四站交流都完成了 | You've completed the conversations at all four stops |

用户明确不想表达赞美时，提供帮助或稍后再来，不让系统为了通关替其改写为正面意见，也不把此情况视为技术错误。

## 5. 店员脚本与回应组合

以下是语义稿，最终播放为经过审核的上海话。

| 台词 ID | 触发条件 | 普通话语义稿 | English gloss |
| --- | --- | --- | --- |
| TEA-N01 | 入座开始 | 请喝茶，觉得怎么样？ | Please enjoy the tea. How is it? |
| TEA-N02 | 只有正面评价 | 很高兴你喜欢。 | I'm glad you like it. |
| TEA-N03 | 只有道谢 | 不客气。茶喝起来怎么样？ | You're welcome. How do you like the tea? |
| TEA-N04 | 评价对象不明 | 你说的是这杯茶吗？ | Do you mean this tea? |
| TEA-N05 | 只是问候或其他内容 | 这杯茶喝起来怎么样？ | How do you like this tea? |
| TEA-N06 | 未理解 | 可以再说一遍吗？ | Could you say that again? |
| TEA-N07 | 用户表达不喜欢 | 知道了。 | I understand. |
| TEA-N08 | 完成保存后 | 不客气，欢迎再来。 | You're welcome. Come again. |

TEA-N07 后由界面给角色练习提示和帮助；不让店员否认用户意见，不擅自换茶或虚构新的交易流程。重复请求直接播放当前适用台词，不生成无限新对白。

主路径 A：N01 → 用户评价 → N02 + 道谢提示 → 用户道谢 → 保存 → N08/回顾。

主路径 B：N01 → 用户“茶很好喝，谢谢你” → 同轮两个意图保存 → N08/回顾；不强行分两轮。

主路径 C：N01 → 用户先谢谢 → N03 → 用户评价 → 保存 → N08/回顾；不要求重复谢谢。

只有在用户明确提交了自己的回应后才判断意图。播放店员、系统自动复述、打开/填入表达卡都不算用户表达；用户主动把示范句提交为回应则可以计入，不因其借助示范而取消有效交流。

## 6. 意图状态、撤回与完成

### 6.1 站点字段

| 字段 | 含义 | 规则 |
| --- | --- | --- |
| tea_evaluation | unknown / positive / neutral / negative / ambiguous | 只针对茶；对象不明记录待澄清 |
| evaluation_evidence | 用户原文、回合和必要上下文 | 不能用任务卡或店员台词当证据 |
| thanks_expressed | false / true | 用户实际致谢，可分轮满足 |
| thanks_evidence | 用户原文/按钮动作及对象 | 引用、否定与学习提问不算实际致谢 |
| unresolved_issues | 评价对象、互相矛盾、撤回不清等 | 非空时不能完成 |
| revision | 当前有效状态修订 | 后续修正改变相关字段 |
| completed_snapshot | 完成时两个意图与证据 | 完成后固定保存，重练产生新记录 |

这里不使用菜品、数量、付款、订单摘要或最终确认字段。两个意图齐备且没有冲突时，服务端直接原子保存完成与事件，然后返回结束台词。

### 6.2 分轮合并与修正

- 未提及的意图保持原值。先道谢，后评价，可以完成；先评价，后道谢也可以。
- 完成前明确撤回或改成负面评价时，更新评价，不能保留此前 positive 继续通关。
- 一轮里“很好喝，不，其实不好喝”以清楚的最终修正为准；存在矛盾且无明确修正顺序时追问。
- 一轮内先合并所有变化与撤回，再判断两个意图，不能边抽取到“好喝”边提前完成。
- 完成状态一旦保存，历史尝试不因之后浏览卡片而变动；继续练习需新尝试。完成后不再提供可能悄悄改写已完成尝试的自由提交框。
- 用户要求重说或不明白时保留既有意图，只提供帮助，不清零让其从头开始。

### 6.3 特殊分支

| 情况 | 处理 | 不应发生 |
| --- | --- | --- |
| 只有评价 | 店员自然回应，UI 提示可道谢 | 店员命令“请谢谢我” |
| 只有谢谢 | 店员问茶如何 | 忽略感谢、要求原样重说 |
| 谢谢 + 风景好看 | 感谢有效，询问茶 | 自动把风景评价转为茶 |
| 茶不好喝 + 谢谢 | 感谢有效，评价负面，给角色提示 | 因好喝/谢谢两个词都出现而完成 |
| “还不错”回答茶问题 | 可接受温和正面 | 只接受固定句“很好喝” |
| “好”对象不清或在答别的问题 | 结合上下文或追问 | 全部肯定词都算赞茶 |
| 系统音频播放完 | 仅记播放 | 当作用户表达 |
| “直接跳到总结” | 返回/结束入口可用，任务仍未完成 | 用导航请求满足两个意图 |
| 后端保存失败 | 保留已收集信息，允许重试 | 先显示完整旅程完成 |

## 7. 本站回顾与四站总回顾

### 7.1 本站回顾

展示简短成功语、E10/E11 两张表达卡、常慢速播放、再次尝试与路线入口。无论语音、文字或按钮完成，核心完成奖励相同。

若显示练习事实，可以写“本次提交了 1 次语音回应 / You sent 1 voice reply”；录音尝试但取消与真正提交分开。不要从识别成功生成准确率、分数或“发音标准”徽章。

### 7.2 路线回顾页

| 区域 | 展示内容 | 数据来源 |
| --- | --- | --- |
| 标题 | 已完成四站，或已完成 x/4 站 | 当前会话四地点的成功尝试汇总 |
| 四站列表 | 地点、任务短句、未开始/进行中/完成/稍后再来 | 各站尝试状态；至少一次成功则显示已完成 |
| 表达回顾 | 每站重点表达入口，仍按双语读音规则 | 已审核内容包；可以学习未完成站表达，但不盖完成章 |
| 练习记录 | 实际语音提交、输入方式和支持使用摘要 | 完整日志；缺失就不显示确定统计 |
| 下一步 | 继续未完成站、重练已完成站、结束本次 | 根据真实进度给主操作 |

用户如果先完成茶楼，标题应是“已完成 1 / 4 站”；不能因为到达设计上的最后一站就显示旅程全部完成。其他站跳过不算成功；重练中也不抹去既有成功。

全程完成计数按四个不同地点各至少一次成功计算，不按总成功尝试次数；在南翔重复完成四次不能得到四站完成。服务端聚合为准，不信任前端页面顺序。

路线回顾可从地图随时打开，茶楼只提供一个自然入口。结束本次会话不会清空已有记录；重新开始需要用户明确操作，沿用设置中的清除/新会话规则。

### 7.3 可选研究反馈

普通体验不强制填写问卷。研究模式如需简短易用性/费力度评分，由独立反馈区承载并记录量表版本；不在未完成交流前插问卷。题目与研究同意流程沿用总方案，不能把情境里“茶好喝”当作对 App 的满意度评分。

## 8. 音频、ASR 与未来升级

### 8.1 音频制作范围

- TEA-N01–N08 共 8 条店员整句常速音频，含正面、追问、未理解与负面回应。
- E10 常/慢速 2 个片段；E11/E12/E01 使用共享库的常/慢速。
- 可选合并句“这茶很好喝，谢谢你”常/慢速 2 个独立片段；若采用，需要新的组合内容 ID 和审核记录。
- 茶这一词语常/慢速各一条作为物件帮助，可在词语库复用；不要求所有装饰物都有发音。
- 环境水声/轻倒茶声作为可关闭装饰声音单独许可和控制，不与语言片段混成不可拆文件。

示范仍以常速整句为主要依据，慢速帮助跟读；注音、中文谐音和自然语块与最终音频逐条对应，不将单字读音拼成整句。

### 8.2 服务与验证

初期使用已选的 `qwen3-asr-flash` 和提前生成的 `qwen3-tts-flash` + Jada 教学音频。实际可用性、发音质量与延迟仍需试用；语音和非语音回应经过相同意图规则。

本站语音验证重点：好喝/不好喝、我喜欢/不喜欢、茶/杯子/风景、单独谢谢、合并表达、引用式提问与明确撤回。ASR 和解释错误分别归因，不能看到两个关键词就标正确。

录音、回听、取消、服务失败、版本和私有资源处理执行[共同约定](Route-drafts-index.md)。遇模型故障，用户仍可提交评价和道谢按钮；选择后经服务端保存，不能在本地假完成。

未来自部署使用同一套评价对象、否定和意图金标准重新比较；TTS 更换则重审对应台词与表达，发布新内容包。无须因换模型重写茶楼界面、回顾页或完成统计。

## 9. 素材制作与视觉验收

| 资产包 | 建议交付 | 细节 |
| --- | --- | --- |
| 地图/外观 | 1 个地标，1 套入口或外观 | 与其他站同风格，有湖心亭辨识元素；资料来源单独记录 |
| 茶室 | 1 套分层场景，桌面/手机两种构图 | 窗景、水面、店员、茶桌、茶具分开；无关键文本烘焙 |
| 角色 | 1 个原创角色 × 4 姿态 | 欢迎斟茶、倾听、回应喜欢、接受感谢 |
| 茶具 | 杯、壶、盘及桌面近景 | 可点击区明确，装饰区域不制造虚假控件 |
| 单站 UI | 任务、对话、学习、双意图提示、完成卡 | 中英/桌面手机四组；评价对象含糊和否定状态有稿 |
| 路线回顾 UI | 全完成/部分完成/有跳过/日志不全四状态 | 站点计数、继续入口、表达回顾清楚 |
| 动效 | 斟茶、回应、结束致意 | 可跳过，低动态替代，完成动作跟随保存 |
| 音频 | 第 8 节店员与学习文件 | 字词、音频、注音、中文近似读音一致 |
| 文案 | 双语任务、脚本、提示、回顾、文化、替代文本 | 英语不残留中文操作提示，核心汉字保留 |

文化卡可沿用完整方案第 9.1 节的湖心亭已引证介绍，强调在虚拟茶席停留并练习表达感谢。新增历史、建筑年代或实际景观视角须另核对；人物、茶具和室内布局按教学创作说明。

UI 验收特别检查：安静不等于空白页面；茶桌、角色和窗景须达到主视觉完整度。输入、读音和帮助保持高可读性，低饱和配色不能导致对比不足。回顾不是塞满统计图的研究者仪表盘。

## 10. 数据与研究观察

| 记录 | 用途 |
| --- | --- |
| 评价对象、极性、证据与上下文 | 区分正确赞茶、夸杯子、负面和歧义 |
| 感谢是否有效、证据及撤回 | 区分真实致谢、否定、引用提问 |
| 两意图出现回合及合并情况 | 观察分轮/合并表达与输入切换 |
| 学习帮助、注音/近似读音、音频及试读 | 解释用户如何完成，不将帮助当失败 |
| 完成快照、模型/规则/内容版本 | 保证完成可追溯，错误归因可复查 |
| 路线回顾打开、继续、重练、结束 | 观察是否理解尚未完成的地点及下一步 |
| 日志缺失与人工帮助 | 避免错误显示精确统计或独立完成 |

建议试运行观察：两个目标是否自然；道谢提示是否显得生硬；英语用户是否知道核心汉字和英文意思的关系；一句完成时反馈是否足够及时；提前进入茶楼的用户是否能理解总回顾尚未完成。

完成分轮话语可作为互动行为结果；没有独立语言测验时，不把它等同于学会礼貌表达或知识迁移。文化卡查看次数也不代表理解文化内容。
