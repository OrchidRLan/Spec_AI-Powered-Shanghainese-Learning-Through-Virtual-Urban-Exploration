## 2. 四站共同执行的已确认要求

1. 正式产品全面重新制作 UI、功能和内容，旧 prototype 只作 progress update。
2. 保留四个地点及其交流目标。UI 和场景质量是核心交付要求。
3. 同时服务普通话背景和主要使用英语的初学者；设置中切换中文/英文。
4. 两种模式都保留核心上海话汉字、对应语言释义和同一套拉丁注音。注音默认显示、可隐藏，按词组对齐。
5. 中文模式另有默认收起的“中文近似读音”，标注“近似读音，请结合音频”。英文模式没有这一入口和内容。
6. 示范音频共用上海话常速/慢速。实际上海话写法、注音、近似读音和音频需制作、审校。
7. 鼓励语音；文字、按钮从一开始就可用。通过任一方式完成交流均可完成任务。
8. 完成、语音尝试、帮助使用分别记录，不能把通关或 ASR 成功当作口语掌握。
9. 初期使用托管 ASR/TTS API，同时预留未来自行部署模型的升级路径。

## 3. 共同体验规格：本轮建议

### 3.1 地图、进入、离开与重练

- 推荐顺序为老饭店 → 梨膏糖 → 南翔 → 湖心亭，四站均可直接进入，不设通关解锁。
- 地点卡显示未开始、进行中、已完成；“稍后再来”标记已跳过但仍可重新进入。
- 返回地图保留已保存的尝试，录音和播放停止；再次进入可继续。普通返回不等于跳过。
- 明确点击“稍后再做”结束当前尝试为 skipped；再开始创建新尝试。已完成后“再练一次”也创建新尝试，旧成功不被覆盖。
- 地图的“已完成”表示至少一个成功尝试；可另标当前重练中，不能因一次重练未完成而抹掉既有成功。
- 刷新恢复服务端已保存状态。纯文字/选择草稿可在当前标签页短期保留；原始录音默认不持久化，丢失时清楚提示重录。
- 全部完成才显示“完成四站”；从茶楼提前结束时如实显示完成了几站，并提供继续入口。

### 3.2 输入和学习支持

| 入口 | 建议行为 | 不应发生 |
| --- | --- | --- |
| 说话 | 点击开始，停止后先回听，用户明确提交；提供重录、取消 | 入店自动录音、停止即不明示上传 |
| 打字 | 可输入上海话汉字、普通话或英语语义；按交流意图判断 | 强制英语用户输入汉字，或把英语完成记为上海话口语 |
| 选择回应 | 选项先进入本地草稿，再点“提交回应”；结构化动作经服务端校验 | 看过或选中卡片就自动更新任务 |
| 表达卡 | 听常/慢速、查看读音、试读回听、填入输入框 | 打开卡片、播放音频、填入文本就当作提交 |
| 修改识别文本 | 明示原转写与编辑稿，编辑后明确重新提交 | 覆盖 ASR 原文，使日志误认为模型识别正确 |

建议文字语义支持中文、英语和上海话书写；拉丁注音用于读音辅助，首版不另承诺任意拼写的注音文本识别。遇到无法理解的注音输入，提供中文/英文或选择回应的入口。

示范录音与任务回应共用录音控件，但目的明确区分；“练习回听”不默认上传。主动提交时才进入 ASR。若开放“把这段用于回应”，仍需一次明确提交。

录音期间点击帮助或切换语言，先停止采集并保留本地录音待用户处理，不静默上传。切换输入方式可保留本地录音和文字草稿，但每次只提交一种来源；离开站点前提醒尚未提交录音会丢失。

### 3.3 双语显示边界

核心表达和已审核的关键店员台词保留上海话汉字、拉丁注音，配当前语言释义。英文模式的导航、任务、按钮功能、菜单解释、订单摘要、错误、文化和回顾均用英语；地名可用英文标题并保留中文招牌作为地点元素。

用户原文或 ASR 原转写放在标明来源的回应区域，不被包装成教学示范；英文用户通过英语“我们理解为……”摘要核对，不依赖读懂汉字转写。按钮可含学习汉字和英语意思，但操作说明必须英语可读。

梨膏糖目标介绍的汉字、注音和译文均按需揭示，例外范围只限这段听辨材料；揭示后遵循同样的双语注音规则。可访问性和文字帮助优先于维持听力形式，使用帮助如实记录。

隐藏拉丁注音是会话偏好，可在设置和表达卡中切换；仅影响注音，不隐藏汉字、释义或音频。中文近似读音按卡片展开，切至英语立即隐藏，返回中文建议恢复收起状态。

## 4. 共同 UI、声音和可访问性基线

以下数值是建议设计基线，需要高保真与设备验收。

- 桌面设计参考 1440×900，手机参考 390×844；补查 320px 窄屏、横屏、200% 缩放和手机键盘。内容溢出应滚动，不压缩文字至难读。
- 正文 16–18px，核心汉字约 24–28px，注音至少约 16px；具体组合按真实长句调整。中文/英文字体使用有相应使用许可的字体或系统字体。
- 点击区域至少 44×44px；正文对比度目标至少 4.5:1。不能只用颜色传达成功、选中、录音或错误。
- 地图四站也提供可键盘操作的地点列表；场景物件有文字替代入口，所有必需操作不依赖拖拽、悬停、颜色或声音。
- 主界面保持场景、当前对话、回复区的稳定关系；手机帮助、选项、确认一次只显示一层主面板。打开/关闭面板管理焦点并返回触发控件。
- 普通状态更新用简短读屏通知，不逐字朗读整段历史；英文模式不让中文辅助标签残留。
- 环境音默认关闭；同一时间只播放一个教学音频。录音时停止所有应用声音，结束录音后不突然恢复环境音。
- 动效建议 160–300ms 操作反馈、600–1200ms 到店转场、1–2 秒完成动作，均可跳过或减少。无实时口型依赖，不用长动画阻塞操作。
- 提示音和成功动画均以保存后的任务状态为准；等待语音期间角色只呈现倾听或等待。

每站必须交付桌面中文、桌面英文、手机中文、手机英文四组关键状态，含最短与最长文本；风格评审与功能验收分别进行。

## 5. 共同技术、恢复与自部署约定

| 部分 | 首版开发边界 | 后续升级约束 |
| --- | --- | --- |
| 前端 | 共用地图、会话、录音、学习卡、对话、设置、状态控件；场景皮肤和站点内容独立 | 更换模型不重做 UI |
| 应用后端 | 校验会话、提交回合、解释语义、执行任务规则、保存进度和日志 | 任务规则不读取提供商专属返回结构 |
| ASR | 沿用初选 `qwen3-asr-flash`，录音提交后通过后端适配器调用 | 自部署加入同一接口；会话绑定配置，不静默切换 |
| TTS | 沿用初选 `qwen3-tts-flash` + Jada，提前生成、审校、保存到项目内容包 | 自部署重新生成新内容版本，重新听审，保留旧包 |
| 理解模型 | 解析意图、字段变更、证据和不确定点；不决定通关 | 更换配置后跑同一批站点用例 |
| 确定性规则 | 校验菜单、单位、否定、状态及确认版本，决定下一步模板 | 研究期间固定规则版本 |
| 按钮通道 | 合法动作直接经规则层校验，可绕过 ASR/LLM | 模型不可用时仍可继续，仍需后端保存 |

API 选择沿用此前方案，不代表本轮实测；实际地区、音色可用性、格式、成本和质量须在 M1 验证。托管模型与 proposal 指定的开放模型分别记录。详见完整方案第 11.3–11.6 节及其中官方依据。

录音建议最长 20 秒、上传 3 MiB；浏览器格式按能力选择，服务端验证并按需转换。密钥仅在服务端，用户录音为私有资源；教学音频和 UI 资产可公开缓存。研究留存沿用完整方案第 14 节，试读回听不自动变成研究数据。

每个尝试只允许一个待处理回合；请求 ID 去重、状态修订号校验、状态与完成日志原子保存。取消或离开后迟到结果不能改变任务。网络重试先查询原请求结果，避免一次动作形成两次订单或重复完成。

| 异常 | 共同恢复要求 |
| --- | --- |
| 麦克风拒绝/不可用 | 本地说明权限问题，文字和按钮立即可用，不扣任务进度 |
| 无声、格式或录音时长问题 | 保留其他信息；解释录音问题，允许重录或换方式 |
| ASR/理解失败或超时 | 不写入猜测字段；保留已知信息与草稿，允许取消、重试或选择回应 |
| 音频播放失败 | 提供重试和文字；糖店文字曝光需记录，其余正常继续 |
| 保存失败 | 不发成功奖励；显示保存问题，查询/重试同一请求，不要求重说整段 |
| 刷新、多标签页或迟到请求 | 以服务端修订为准；旧确认不可用，显示当前有效摘要 |
| 内容资产缺失 | 阻止未审核教材进入正式构建；运行时用可读文本和恢复入口，不显示损坏图标或空白操作区 |

性能沿用总方案的初始预算：ASR 12 秒、理解 8 秒、单回合约 25 秒超时；语音中位数 5 秒、95 分位 10 秒是待验证目标。建议当前场景压缩视觉资产首屏预算 3 MiB、进入后预取关键音频；另测冷缓存、弱网和手机实际可交互时间，不能用素材加载完成冒充用户可操作。

## 6. 内容与资产制作的共同流程

1. 先审阅每站语义脚本、意图、界面和分支，再把台词改写为自然上海话。
2. 两名流利使用者检查上海话写法、可接受变体与中英文释义；具体注音规范统一后制作，不从普通话字面机械转写。
3. 为表达建立汉字词组、拉丁注音、英文/中文意思的对齐记录；中文谐音按批准读法制作并经初学者试读。
4. 先完成南翔数量、外带、确认三组样例，再覆盖四站。核心表达常/慢速都审校，长句按自然语块处理，不拼接单字音。
5. 店员台词用有限模板和整句音频。只有允许的参数组合才提供对应音频；异常输入用通用已审核上海话追问，精确错误解释用界面语言文字。
6. 音频生成记录来源、模型、声音、文本、语速、配置、校验值和审核。新内容不得覆盖已绑定研究会话的旧资产。
7. 插画分层交付，数字、任务和按钮文字不烘焙在背景。角色原创；真实店铺资料只作有来源的参考，教学室内与菜单不冒充实景复刻。
8. 图片记录作者、来源/许可、用途、替代文本、裁切安全区和版本；音频记录字幕关联；设计文件记录字体和组件状态。

各站音频表列出逻辑台词，不等于“表格行数就是文件数”。参数必须展开为明确的完整句版本，常/慢速分别计数；可复用的 E01/E05/E11/E12 只在共享内容库制作一份，以 ID 引用。

## 7. 开发组织、共同验收与审阅重点

先做南翔，验证共用组件和语音链路；随后老饭店、梨膏糖和茶楼在各自设计/内容就绪、人员允许时可以并行实现。人员不足时推荐按老饭店 → 梨膏糖 → 茶楼推进；这是资源安排，不是站点业务的硬依赖。游览顺序仍按地图建议。

整体并行安排：步骤 1–4 按子任务并行；步骤 5 开发期间继续其他站的设计和内容；步骤 6–8 可并行；步骤 9 可与步骤 10 的发布准备并行，但正式上线在步骤 9 验收之后。逐步前置条件和交付限制见 [产品开发步骤第 13 节](Product-development-roadmap.md#13-执行依赖与阶段产物)。

| 工作包 | 交付 | 依赖 / 完成依据 |
| --- | --- | --- |
| 步骤 1：设计 | 共用设计系统、地图、各站桌面/手机高保真 | 双语与语音/错误/确认等状态均有可实现设计 |
| 步骤 2：素材与内容 | 四站图层、角色、台词、注音、翻译与音频包 | 实际上线内容审核通过，ID 和版本清楚 |
| 步骤 3–4：基础与能力 | 前后端、共用界面、会话、输入、声音、规则与日志 | 真实服务可用，模型失败时可换输入，恢复可靠 |
| 步骤 5–8：逐站实现 | 南翔、老饭店、梨膏糖、湖心亭 | 每站独立可完成，分别通过 20/16/18/20 项用例 |
| 步骤 9：整合与质量修正 | 全路线、视觉对照、兼容与恢复检查 | 工程人员验收，无已知关键流程或视觉缺陷 |
| 步骤 10：部署交付 | 完整网址、源文件、配置与维护说明 | 实际环境能完成四站，资源权限和版本正确 |

每站验收表之外，四站都要检查：纯按钮完成、中文和英文文本完成、混合输入、真实语音、语言切换、注音显隐、中文谐音边界、手机键盘、键盘/读屏、减少动态效果、音频失败、麦克风失败、迟到请求、重复提交、保存失败、刷新恢复、离开/重练、完整日志与模型来源。

当前验收由开发过程中的规则、接口、视觉、内容和真实设备检查组成，不招募参与者做用户测试。上海话文字、注音与音频仍需语言审核，这是内容制作的质量要求。

审阅时可以集中看五件事：每站是否有吸引力；操作是否过多；UI 是否达到期待；内容是否适合两类初学者；任务判定是否符合交流目标。素材实际制作、语音审校和接口试用结果会在后续版本补录。
