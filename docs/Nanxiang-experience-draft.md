关联：[四站审阅入口与共同约定](Route-drafts-index.md)、[完整开发方案](Development-blueprint.md)、[P1 决策记录](P1-draft.md)。  
范围：完整产品与开发规格；当前不编写应用代码，不生成未经审核的上海话注音或音频。

实施按 [产品开发步骤](Product-development-roadmap.md) 第 5 步。本文件中的研究观察、初学者试运行与访谈建议保留为范围外参考；本轮只要求内容审核、功能、视觉与设备等工程验收，不以用户测试作为交付条件。

## 1. 本站定位

用户在有蒸笼、出餐台和打包区的店铺中，与店员完成一笔小订单：给自己和同行的人买两份小笼包，带走，核对订单后看到真实对应的打包反馈。

建议本站作为第一个实现并验证完整链路的场景。它覆盖商品、数量、单位、用餐方式、否定修正和确认，能检验共用录音、学习卡、模型适配、状态保存与日志。开发先做南翔，不改变地图推荐的游览顺序。

地图名称：“南翔馒头店 / Nanxiang Steamed Bun Restaurant”。任务标题：“两份小笼包，打包带走 / Two servings of xiaolongbao to go”。目标体验约 5–6 分钟，不设强制语音次数或限时。

菜单只聚焦小笼包，数量提供一、二、三份，方式提供堂吃或外带。数量和方式选项用于表达与修正，不要求任务接受任意订单。无真实价格、付款、配送、预约或现售规格。

## 2. 页面组成与连续流程

主路径：地图卡 → 到店任务 → 点两份 → 表达外带 → 核对 → 打包回顾。用户可一句说全，也可先说外带，再补数量。帮助在任何交流阶段可用。

| 页面 ID | 呈现 | 主要动作 | 状态边界 |
| --- | --- | --- | --- |
| NX-01 地图卡 | 建筑小图、任务预告、未开始/进行中/完成状态 | 进入/继续、关闭 | 不把任务目标预填入订单 |
| NX-02 到店任务 | 门面到柜台短转场、店员与简短任务卡 | 开始、返回地图 | 开始不自动录音，转场可跳过 |
| NX-03 柜台交流 | 店员、蒸笼、打包区、当前对话、订单草稿、输入区 | 说/写/选、查看单位、听重播、看帮助 | 订单只显示实际被理解和保存的信息 |
| NX-04 学习抽屉 | 数量、外带、确认及重说表达 | 常/慢速、读音帮助、试读回听、填入 | 不自动提交或更新订单 |
| NX-05 核对订单 | 两份商品示意、外带摘要、店员确认句 | 确认、修改、语音/文字回应 | 确认绑定已展示的当前订单版本 |
| NX-06 打包回顾 | 保存成功后店员打包、递袋，展示结果与表达 | 下一站、回地图、重练 | 只有已完成才显示完成章 |

普通返回地图保留已提交进度；再次进入继续。明确“稍后再做”记为 skipped，再开始新尝试。完成后重练也新建尝试，既有成功保留。

### 2.1 任务卡与目标提示

中文：“给自己和同行的人买两份小笼包，打包带走，并核对订单。”

English: “Order two servings of xiaolongbao to take away, one for you and one for your companion. Check and confirm your order.”

开始后收为“查看任务 / View task”。订单信息初始为“商品待说明 · 数量待说明 · 堂吃/外带待说明”；不能因为任务卡写了两份外带就给用户显示一张已经点好的订单。

### 2.2 柜台主界面

桌面建议：轻量顶部导航；中央店员和蒸笼作为主画面；下方稳定对话与回复区；订单条靠近柜台但有清楚实色底。表达帮助按需从侧边展开。

手机另做近景：店员和蒸笼相对靠近，打包区保留可识别局部；订单压缩为一行可展开摘要。键盘打开时收缩场景，当前问题与提交保持可见。帮助、选项、核对一次只展开一个主要面板。

输入区常驻“点击说话 / Tap to speak”“打字回应 / Type a reply”“选择回应 / Choose a reply”“看看怎么说 / See how to say it”。使用按钮无需先经历识别失败。

### 2.3 物件互动与回应提交

- 点蒸笼：打开小笼包与“份”的说明，允许听词语示范；不自动下单。
- 点打包袋：打开外带表达卡；不把 takeaway 改为 true。
- 点数量：形成本地选择草稿；“提交回应”之后才向店员表达。
- 点“填入回应”：把句子放入文字框，可编辑再提交；不自动发送。
- 核对面板的“确认订单”是明确的最终提交，无需再次弹确认框；语音或文字确认也有效。

本地草稿与已接受订单分开显示。例如选了三份但尚未提交，订单仍是此前两份，选择面板标“待提交 / Not sent yet”。

## 3. UI 艺术与反馈设计

### 3.1 场景方向

推荐温暖、精致、有生活气息的分层插画。构图由前景竹蒸笼和木柜台、中景店员、后景窗格工作区、侧边包装区组成；通过材质、光线和动作形成到店感。

| 维度 | 具体建议 |
| --- | --- |
| 色彩 | 米白 #F7F1E7、竹棕 #C6A579、木褐 #8A6044、深青绿 #245C52，少量朱红 #A4483C；文字底面保持实色 |
| 角色 | 原创店员，欢迎、倾听、回应、核对、递袋五个关键姿态；声音与初期 Jada 配置协调 |
| 商品 | 一份蒸笼示意、小笼包近景、打包盒、袋子与简洁餐具；不标未核实每笼只数 |
| 动效 | 到柜台、听取回应、订单更新、打包装袋四类；蒸汽轻量可关闭 |
| 排版 | 核心汉字与拉丁注音按词组绑定，英文订单允许换行；单位不可只靠图片表达 |
| 完成印章 | 小型地点纪念章配“已完成”文字，不给语音路径额外星级 |

标题可用有文化气质且许可清楚的衬线字体，正文和按钮使用易读无衬线。所有输入、单位和错误状态均遵循共用字号、对比度和 44px 点击区域基线。

### 3.2 数量与包装的视觉约定

本练习明确“一笼示意对应一份”，不宣称真实门店每份装法。两份要画成两个份量单元，不能仅画两只包子。一个外带袋可以装两份，完成画面必须同时显示“两份 / Two servings”。

订单未确认时只出现数量预览；服务端保存完成前，不播放封盒、装袋或递袋成功动作。用户选择堂吃时可以显示堂吃标签，但不为符合目标而偷偷切换外带。

减少动态效果时呈现静态的订单、包装与完成结果，不强制等待动画。环境音默认关闭，示范和录音优先；录音时停止应用声音，店员不会一边播放音频一边等待用户说话。

## 4. 菜单与语言内容

### 4.1 内容字典和单位

| 内容 ID | 中文 | English | 规则 |
| --- | --- | --- | --- |
| NX-ITEM-XLB | 小笼包 | Xiaolongbao | 唯一教学商品，附简短英文描述 steamed soup dumplings |
| NX-UNIT-SERVING | 一份 | One serving | 一个练习份量；本练习的一笼示意对应一份 |
| NX-Q1 / Q2 / Q3 | 一份 / 两份 / 三份 | One / Two / Three servings | 初始不预选两份；其他值不满足任务 |
| NX-MODE-HERE | 堂吃 | For here | 明确 false，不是未知 |
| NX-MODE-GO | 外带 / 打包带走 | To go / Take away | 明确 true |

当店员刚问“要几份？”时，回答“两”可以结合问题单位理解为两份；日志注明上下文。无明确单位上下文的“两个”需问两只还是两份，不能凭任务目标补成两份。

“两笼”在已向用户说明一笼对应一份的教学规则下可接受；“两只小笼包”不满足两份。“二百份”等异常数值保留原转写并进入澄清，不能擅自改成两份。

### 4.2 核心表达

| ID | 上海话汉字候选，待审校 | 普通话意思 | English meaning | 重点 |
| --- | --- | --- | --- | --- |
| E08 | 我要两份小笼包 | 我要两份小笼包。 | Two servings of xiaolongbao, please. | 数量与商品 |
| E09 | 打包带走 | 打包带走。 | To go, please. | 外带意图 |
| E05 | 对个 | 对的。 | Yes, that's right. | 对当前摘要确认 |
| E12 | 请侬再讲一遍 | 请再说一遍。 | Could you say that again? | 主动请求帮助 |
| E01 | 侬好 | 你好。 | Hello. | 可选开场 |

全站重点只有数量、外带、确认三类；问候不是通关条件。补充单位、堂吃与修改支持，避免让用户必须学习完整点单词汇表。

两种模式都有：汉字、词组对齐拉丁注音、当前语言意思、常/慢速上海话。注音默认显示可隐藏；中文“中文近似读音”默认收起，标注“近似读音，请结合音频”；英语没有该入口。核心汉字、意思、近似读音分别维护。

### 4.3 首批三组内容样例的交付规格

这是已经约定优先制作的样例范围，本版先确定内容结构，不虚构音标、谐音或样音。

| 样例包 | 要交付的内容 | 审核重点 |
| --- | --- | --- |
| 数量 E08 | 最终上海话汉字、两种释义、词组注音、中文近似读音、两种读法说明、常/慢速 | “两份”是否清楚，与两只的区别、完整句自然度 |
| 外带 E09 | 同上，加堂吃/外带对照与使用情境 | 否定堂吃和肯定外带是否被正确理解，近似读音是否误导 |
| 确认 E05 | 同上，加“什么时候能用这句”的例子 | “对”须回答一个已展示摘要，不能把任何肯定都当订单确认 |

三组都需参考读法、双人语言审核、音频听审和初学者试读；通过后用真实内容做高保真排版，再扩展其他站。实际上海话写法可以改动，ID 与语义目标保持稳定。

## 5. 店员脚本与主路径

以下为普通话语义与英文释义，实际上海话需改写审核；不直接用普通话文字生成所谓上海话示范。

| 台词 ID | 触发 | 普通话语义稿 | English gloss |
| --- | --- | --- | --- |
| NX-N01 | 开始 | 欢迎，想买什么？ | Hello. What would you like? |
| NX-N02 | 数量未知 | 要几份？ | How many servings? |
| NX-N03 | 用餐方式未知 | 堂吃还是外带？ | For here or to go? |
| NX-N04 | 单位不明 | 你说的是两只，还是两份？ | Do you mean two dumplings or two servings? |
| NX-N05 | 数量与目标不符 | 这次需要两份，要改一下吗？ | This time you need two servings. Would you like to change that? |
| NX-N06 | 明确堂吃 | 这次要带走，要打包吗？ | This order is to take away. Would you like it packed? |
| NX-N07 | 商品超出菜单 | 这个练习里可以点小笼包。 | In this activity, you can order xiaolongbao. |
| NX-N08 | 数量仍不清 | 可以再说一下要几份吗？ | Could you tell me again how many servings? |
| NX-N09 | 全部有效，生成核对 | 两份小笼包，外带，对吗？ | Two servings of xiaolongbao to go. Is that right? |
| NX-N10 | 完成保存成功 | 好的，给你打包。 | All right. We'll pack them for you. |
| NX-N11 | 修改指向不明 | 你想改数量，还是用餐方式？ | Would you like to change the quantity or whether it's to go? |
| NX-N12 | 未理解有效信息 | 可以再说一遍吗？ | Could you say that again? |

标准路径：用户提交“两份小笼包” → NX-N03 → 用户提交“打包带走” → NX-N09/核对面板 → 用户确认 → 保存 → NX-N10/递袋。

一步完整输入：用户提交“两份小笼包外带” → 同轮保存商品、数量与方式 → 直接核对。不能额外重复问数量或方式。

拆分输入：用户先说“外带” → 保存外带 → 补商品/数量；在唯一商品已明确的上下文中“要两份”可关联小笼包。未建立商品上下文时不能任意补充。

## 6. 完整分支与修改行为

| 输入/情况 | 判断 | 下一步 |
| --- | --- | --- |
| 只有“小笼包” | 商品有效，数量和方式未知 | 先问数量，再问方式 |
| “一份小笼包外带” | 保留一份和外带，数量不满足目标 | 提醒两份，只需修改数量 |
| “两个”且单位不明确 | 记录单位待澄清 | 问两只还是两份，不进入核对 |
| “两笼” | 根据已展示教学单位归一为两份 | 保留原说法与归一依据 |
| “堂吃” | takeaway=false | 提醒任务外带，不能当作没有说 |
| “不堂吃，要打包” | 解析否定和修正为外带 | 保留其他字段，条件齐全则核对 |
| “不要打包” | 明确拒绝外带，通常可理解堂吃；若语境冲突则追问 | 不仅因为出现“打包”就记录 true |
| “两份，不，三份” | 最终清楚修正为三份 | 保存三份并提示目标不符 |
| “两份还是三份都行” | 数量有歧义 | 追问，不猜两份 |
| 核对时“对，改成三份” | 先改数量，旧摘要失效 | 提示数量目标并等待再次核对 |
| 核对时“没听清” | 重播请求 | 不确认 |
| 尚无摘要时“对的” | 没有可确认对象 | 继续补缺项 |
| 仅点蒸笼或打包袋 | 学习/查看动作 | 不写 item、quantity 或 takeaway |
| 点两份但未提交 | 本地草稿 | 订单不变，显示待提交 |
| 问多少钱/要其他商品 | 超出教学菜单 | 短说明当前练习范围，保留已知字段 |
| ASR 转写为异常数量 | 保留原文并标为不可靠输入 | 澄清或让用户改文字，不自动纠错为目标 |

若一轮内部分字段明确、部分含糊，保存明确字段，对含糊部分追问；不能整轮丢弃，也不能把含糊信息补成默认值。

## 7. 站点状态与订单版本

### 7.1 数据字段

| 字段 | 含义 | 校验 |
| --- | --- | --- |
| item | xiaolongbao / unknown | 明确表达或唯一有效菜单上下文 |
| quantity | 数量或空 | 不把未知当 2；合法但错误的 1/3 可保存供纠正 |
| unit | serving / basket / piece / unknown | basket 按已说明约定归一，piece 不等同 serving |
| normalized_servings | 可确认的标准份数或空 | 仅单位明确时计算 |
| takeaway | true / false / unknown | false 表示堂吃，不能当缺失或外带 |
| unresolved_issues | 单位、修正、未知商品、异常数值等 | 非空阻止完成 |
| revision | 有效状态修订 | 新变更产生新版本 |
| summary_revision | 最近已展示核对摘要版本 | 数据与图像必须相同 |
| confirmed_revision | 用户明确确认版本 | 必须匹配当前已展示摘要 |

初始全部未知；任务目标保存在独立任务定义，不复制到用户订单。合法但不符合目标的字段应显示真实理解结果；未知或无效修改形成待澄清项，不能悄悄沿用旧订单通关。

### 7.2 完成条件与提交顺序

同时满足：小笼包、标准两份、外带为 true、无未解决问题、用户明确确认当前已展示版本、完成状态成功保存。

每轮执行顺序为：校验请求和旧版本 → ASR/解释或结构化按钮动作 → 合并本轮有效字段/撤回 → 校验单位与目标 → 追问或展示摘要 → 后续有效确认保存完成。理解模型不直接输出权威完成状态。

订单内容修改后旧确认立即失效。首次一句“我要两份外带，对的”可以填完整字段，但不能确认尚未展示的核对面板。同一已展示订单上的重复确认通过请求去重仅记一次完成。

## 8. 确认面板与完成回顾的规格

核对面板采用轻纸质订单风格、实色高对比文字；轻微纸纹不能影响辨识。包含商品图、两份数量、外带标签、店员核对句与音频，以及确认/修改。

确认阶段仍允许三种输入，不能只剩鼠标按钮。“修改”展开数量与方式编辑，当前值保留；提交修改后重新校验。如果改为堂吃或一份，回到补充阶段，不能继续使用旧有效确认。

完成后递一个含两份的袋子，旁边显示明确数量；回顾优先 E08/E09/E05 三张卡。普通话/英文结束语分别为“你完成了这次点单”和“You completed this order”。若显示练习统计，只写“尝试语音 2 次”等事实。

下一站建议为湖心亭；如果湖心亭已完成而其他站未完成，优先推荐未完成地点。全部完成后主按钮变为查看路线回顾，始终可以回地图或再练一次。

## 9. 语音内容、服务与自部署

### 9.1 基础制作量

- NX-N01–N12：12 条店员整句常速音频；核对只需要正确两份外带的一种完整句。错误的具体数值用当前语言界面说明，配通用已审核追问。
- E08/E09：常、慢速各一条，共 4 个新增基础片段。
- E05/E12/E01：复用共享库的常、慢速音频；三组首批样例中 E05 必须先完成审核。
- 补充单位“一份/两份/三份”、堂吃和商品名：建议 5 个词语/短语各两种语速，共 10 个支持片段。若与批准表达实际完全相同可按内容 ID 去重。
- 组合句“两份小笼包外带”可后续添加为可选整句示范，需独立录制/合成、注音与审核，不用单字或短句粗糙拼接。

### 9.2 API 与验证

初期 ASR 沿用 `qwen3-asr-flash`；TTS 沿用 `qwen3-tts-flash` + Jada，经 API 提前生成和审核后入库。当前未调用或验证本站效果，不把它们写成 proposal 开放模型的实验输出。

本站第一轮 ASR 样本至少覆盖两份/两只/两笼、堂吃/外带、不要/要、先数量后方式、一次说全、修改数量和确认。具体批量数量沿用总方案约 20 条小规模初测，再形成完整站点金标准集。

审核音频关注份量词清晰度、自然连读、常慢速一致、否定与确认的语义；中文谐音依据批准音频编写，难以近似的声音用说明和音频处理。

### 9.3 自部署升级

ASR 适配器输出统一转写和配置来源；未来 Qwen3-ASR-1.7B 或其他候选通过同一数量/否定/修正测试后再换配置。TTS 自部署通过同一内容制作入口生成新版本，全部听审后发布，不改变前端卡片与音频 ID 的用途。

ASR 与 TTS 可以分别升级；不要求运行中的 App 实时合成店员台词。会话绑定模型和内容版本，更换在新会话/批次进行，旧配置与资产可回退。

## 10. 异常、恢复与低门槛完成

| 故障/操作 | 用户看到什么 | 数据处理 |
| --- | --- | --- |
| 麦克风拒绝 | 无法录音，仍可打字或选择 | 不记实际录音成功，不清空订单 |
| 空录音/格式错误 | 录音未能使用，可重录 | 不写数量或方式 |
| ASR/理解超时 | 当前回应暂未处理，可取消/重试/换方式 | 原请求结果可查询，取消后迟到结果不生效 |
| 网络中断 | 保留已知订单与本地文字草稿 | 恢复后取服务端最新修订 |
| 保存失败 | 未完成保存，允许重试 | 不打包、不盖章；同一请求幂等恢复 |
| 刷新 | 恢复已保存订单；未提交录音可能需重录 | 不自动提交旧录音，不生成新订单 |
| 核对时切语言 | 英文/中文摘要对应同一订单 | 不重置修订或确认状态；隐藏中文近似读音 |
| 录音时打开帮助 | 停止采集，保留待处理录音，显示帮助 | 不静默上传；用户明确决定提交或丢弃 |
| 点击返回地图 | 停止录音/播放，保留提交进度 | 在途请求取消/过期，不跨站更新 |

录音最长、大小、单回合预算、资源权限与日志留存沿用[共同约定](Route-drafts-index.md)。按钮路径不调用 ASR/理解模型，但仍由后端校验并保存；模型不可用时可完成，后端不可用时不能伪装成功。

## 12. 数据记录与研究问题

在共用日志上额外关注：

- 原始数量和单位、归一后的份数及依据，避免日志只剩“2”而无法判断两只误判。
- 外带字段统一使用 takeaway，明确区分 true/false/unknown，便于跨模型对比。
- 字段首次给出、修改、撤回与拒绝原因；一句多字段是否正确保存。
- 每次摘要修订及确认来源，旧确认是否正确失效。
- 点物件、查看单位、近似读音、注音隐藏、常/慢速及试读回听的帮助使用。
- 语音实际采集、提交、转写、人工编辑、按钮/文字切换，及各阶段耗时。

本站试运行观察：用户是否把两份理解成两只；是否把物件点击误认为已下单；是否发现文字/按钮；核对是否自然；英语用户能否在不读汉字的情况下知道订单内容。

研究报告区分系统理解、任务达成与语言能力。通过两份外带订单，不能自动得到“数量词发音正确”或“掌握上海话点单”的结论。

## 14. 开发拆分、依赖与完成标准

| 工作包 | 要交付什么 | 完成证据 |

本版扩展了原草案的规则、内容、技术、数据和验收；保留原有六种呈现、分层柜台艺术和实际确认后再打包的设计方向。审阅重点是场景完成度、数量单位表达、学习支持层级及核对过程的自然程度。
