## 3. 组件约定

`StationScene` 接收 `station: restaurant | candy | teahouse`，复用 `ScenePose`。可选输入为 `selectedDish`、`selectedFlavor`、`completed`、`label`、`className`。

- 菜品稳定 ID：`fish`、`chicken`、`tofu`。选择图由 `DishIllustration` 输出。
- 口味稳定 ID：`rose`、`osmanthus`、`mint`。选择图由 `CandyIllustration` 输出。
- 糖店场景没有隐藏目标参数。`selectedFlavor` 只使用用户明确选择的值，且仅用于完成后的两包交付；介绍时三种商品均等展示。
- `completed` 必须来自成功保存结果。返回已完成记录时直接展示静态 `packed`；保存当下可用 `packing` 播放一次短交付动作。
- 场景只负责呈现，不更新答案、进度、声音播放或完成状态。未知菜品显示空盘，未知口味显示中性梨形包装，不猜测其他有效选项。
- 中英场景替代文本由父组件按当前语言提供。选择插图与相邻可见标题重复时可不传 `label`，作为装饰图从读屏隐藏；有独立含义时传入当前语言名称。
- 所有定义、标题、渐变和纹样的 ID 使用 React `useId` 隔离，允许同页面多次引用。

## 4. 动态与无障碍

角色在 `speaking` 时使用轻微口型与手势，`listening` 时手靠耳侧并略偏头，`thinking/checking` 时手靠下颌，`acknowledging` 时短暂点头。动作只表达界面状态，不声称实时口型同步或情绪识别。

呈菜、递袋和倒茶为短动作，不设阻塞计时。茶汽和水纹低频缓动。系统 `prefers-reduced-motion` 与应用 `html[data-reduced-motion=true]` 都关闭动画；倾听、思考、完成等仍保留不同静态姿态，倒水线不残留悬空。

标准场景为 `1100 × 580`。600px 以下采用约 `1.45:1` 的中心近景，主角色、三款糖包装、菜单、选中菜、茶盘仍在可见范围。文本和控制区域由页面单独布局，不把长句放进复杂纹理或 SVG 中。

实际练习页的手机容器采用 `1.4:1`，SVG 宽高均填满容器，由 `xMidYMid slice` 居中裁切；不使用超宽 SVG 加负边距，以避免共用南翔样式覆盖宽度后出现单侧空带。站点作用域样式优先于旧南翔容器规则。
